AIVAULT 電子法律教材使用說明
作者：AIVAULT
版本：2026 測試版
說明：介紹 AIVAULT 與電子書閱讀、暗星解說。封面圖由使用者自行設計後，於教材匯入頁上傳。本檔僅含原文，不含封面、不含假進度。

第一編　AIVAULT 是什麼

第一章　定位

第一節　不是聊天網站

第1條
AIVAULT 是 AI 公司正在工作的任務舞台與共同記憶中心。各項 AI 溝通與任務經由 AIVAULT 協作，保留未來更換 AI 的接口。它不是一般聊天室，也不把某一家模型寫死在產品核心。

第2條
Technical Dark Star（技術暗星）是 AIVAULT 裡的工程與解說助理。學生可以跟暗星說話、傳檔、問法律問題。電子書是教材原文；暗星是解說助理。兩者必須分開，暗星不能把自己寫的說明冒充成法律條文或教材原文。

第3條
本說明書用來做兩件事：第一，讓第一次進來的人知道 AIVAULT 與電子書怎麼開；第二，用來測試電子書前台是否只依頁碼向後端取頁、目錄能否跳頁、暗星解說會不會標來源。

第二章　現在可以從哪裡進去

第一節　工作中心

第4條
暗星的工作中心頁是 aivault-home.html。頂部有按鈕：AI 協作池、教學助理、電子書。點「電子書」進入閱讀器 dark-star-ebook.html。尚未選書時，畫面只顯示「選擇教材」，不會出現假書名、假章節或假進度。

第5條
若使用 GitHub Pages，工作中心網址為：
https://m9wmtcb782-arch.github.io/AIVAULT/aivault-home.html
電子書閱讀器：
https://m9wmtcb782-arch.github.io/AIVAULT/dark-star-ebook.html
教材匯入：
https://m9wmtcb782-arch.github.io/AIVAULT/dark-star-ebook-editor.html
暗星主頁 technical-dark-star.html 本次規格禁止修改，電子書入口加在工作中心，不改暗星主檔。

［第 2 頁］
第6條
管理員匯入教材的頁面是 dark-star-ebook-editor.html。建立書、上傳文字、查看匯入進度、finalize，都在這一頁。封面圖不由系統產生，由你自己設計後再上傳。

第二編　如何選書與閱讀

第一章　選哪一本

第一節　選書畫面

第7條
進入電子書後先選書。可做兩件事：一、點本機書目裡已經成功匯入的書；二、手動輸入 ebook_id（UUID）後按「開啟教材」。後端目前沒有公開的書單 list action，因此書目只來自匯入成功紀錄或你輸入的編號，系統不會編造書單。

第8條
閱讀中可按「選書」回到選書畫面，再換另一本。同一瀏覽器會記住 reader_id，方便之後恢復閱讀位置。reader_id 只是讀者編號，不是管理員權限。

第二章　閱讀器功能

第一節　書本畫面

第9條
閱讀器要像書，不是 PDF 播放器，也不是整頁 textarea。桌面寬螢幕顯示左右頁與中央裝訂線；手機單頁。封面、書名、作者、版本顯示在左側資訊欄。沒有封面檔時，只顯示書名排版，不拿別人的圖冒充封面。

第10條
翻頁方式：
一、按鈕「上一頁」「下一頁」。
二、桌面點書頁左三分之一或右三分之一。
三、鍵盤左右鍵、PageUp、PageDown。
四、手機左右滑動。
翻頁時有書頁動畫。只向後端取目前頁，並可預載前一頁與下一頁，不一次載入整本。

第11條
頁碼顯示在書頁下方。可在頁碼框輸入數字跳頁。閱讀進度條依目前頁與總頁數計算。離開後再進來，會用 progress 向後端讀上次頁碼；後端若權限不足，前台會停在可讀狀態並顯示真實錯誤，不假裝已恢復進度。

第二節　目錄

第12條
目錄使用 action「toc」，依後端回傳的編、章、節、條顯示。點目錄項目跳到該筆的 page_number，前台不自己猜頁碼。若後端尚未 finalize 或表格權限不足，目錄區會寫出 HTTP 狀態與錯誤原文。

第三編　暗星解說

第一章　一邊看書一邊問

第一節　詢問暗星

第13條

［第 3 頁］
畫面主區是教材原文，右側（手機則由「詢問暗星」打開）是解說區。學生可問例如：「這一頁在講什麼？」「這一條是什麼意思？」「請用大學生能理解的方式解釋。」「這一條跟上一頁有什麼關係？」「請舉一個生活中的例子。」

第14條
前台送給暗星的內容包含：ebook_id、書名、頁碼、章、節、條號、目前頁原文，以及必要的前後頁。不把整本書送給暗星。暗星經由既有 ai-gateway，engine 為 technical-dark-star。不另開一套模型入口，不把 Gemini 或 Groq 的金鑰放在前端。

第15條
解說區必須分開三塊：
【教材原文定位】目前讀到哪一頁、哪一條。
【暗星解說】AI 寫的說明，只是解說，不是條文本身。
【來源】至少包含書名、版本、頁碼、條文。例如：「依本書第10頁、第10條……」
沒有真實頁面資料時，不產生假的暗星答案。

第16條
暗星不能取代電子書。教材原文始終留在書頁上，解說寫在旁邊。學生要核對時，以書頁原文為準。

第四編　管理員如何把這本說明變成電子書

第一章　匯入步驟

第一節　建立與分塊

第17條
打開 dark-star-ebook-editor.html。填書名、作者、版本、說明。封面欄位可先空著，等你的封面圖做好再選檔上傳。正文可直接貼上本檔全文，或選擇本 .txt 檔。

第18條
按「預覽字數」確認總字元與將分成幾個區塊。chunk 預設約 20,000 字。本說明字數低於一塊，匯入時通常只有 sequence 0。以後正式法律教材若有數十萬字，會依序 append sequence 0、1、2……再 finalize。禁止一次把整本 30 萬字打進單一 POST。

第19條
按「開始匯入」會依序呼叫：
action create（書名必填）
action append（job_id、sequence_no、content）
action status（用 job_id 查匯入狀態）

［第 4 頁］
完成後再按 finalize，由後端解析編章節條、產生頁面與目錄。畫面會顯示已上傳字數、區塊數、進度與後端回傳。失敗時記錄：API action、request、response、HTTP status、錯誤訊息。不要為了畫面好看而改後端。

第20條
發布、封存按鈕會送 publish、archive。若後端回 unknown action，匯入頁會照實顯示。本機書目只在 create 或 finalize 真正拿到 ebook_id 之後才寫入，供閱讀器選書使用。

第二章　測試這本說明時要看什麼

第一節　前台測試清單

第21條
測試時依序確認：
一、工作中心看不看得到「電子書」按鈕。
二、閱讀器先出現選書，不出現假書。
三、匯入本檔後，若後端成功，選該本，應看得到書名、作者、版本。
四、第1頁、中間頁、最後頁是否只能靠 page_number 取得。
五、目錄點「第10條」是否跳到後端給的頁碼。
六、左右翻頁、滑動、鍵盤是否可用。
七、詢問暗星時，回答是否帶【來源】且不覆蓋書頁原文。
八、關掉再開，是否嘗試恢復頁碼。

第22條
實測後端入口為：
https://clcddygkaaqqtsbswgdf.supabase.co/functions/v1/dark-star-ebook-ingest
前端只帶公開 anon key。若 create 回傳 permission denied for table dark_star_legal_sources，代表表格尚未開放給呼叫端寫入。這不是前台造假，也不是這本說明寫錯。待後端授權或改為 Edge Function 內部權限後，用同一份原文再匯入即可。

第23條
封面圖由你設計。建議直式、接近書封比例（約 3:4），檔案用一般網頁圖片格式。做好後在匯入頁「封面」選檔。未上傳前，閱讀器只顯示書名封面，不會用其他圖片頂替。

第五編　使用時的界限

第一章　原文與解說

第一節　法律學習用途

第24條

［第 5 頁］
本系統若日後放入法律教材，原文是教材，解說是助理。引用時應寫明書名、版本、頁碼、條號。AI 解說可以舉生活例子、改寫成大學生能懂的句子，但不能把解說寫成好像條文本身。

第25條
禁止事項（前台已遵守，使用時也不要要求系統去做）：
不要修改 Technical Dark Star 核心、AI Gateway、既有暗星語音、Gemini／Groq 供應方式。
不要重建資料庫，不要另做一套 ebook API。
不要把整本書塞進瀏覽器或每次都送給暗星。
不要用假資料冒充真實電子書。
不要刪除既有 AIVAULT 功能。

第26條
閱讀器提供「暗星朗讀本頁」。朗讀的是目前頁【教材原文】，開頭會說明這是書上的字，不是暗星自己寫的。可按「停止朗讀」。解說區另有「朗讀解說」，只朗讀暗星的說明，並先聲明不是原文。朗讀使用裝置內建語音，不改暗星主頁既有即時語音。

第27條
學生在解說區向暗星提問。可打字，或按快捷句。暗星依目前頁與前後文回答，並標【來源】。這是提問暗星，不是暗星出題考學生。

第28條
本說明到此結束。下一動是：你完成封面圖，將本檔與封面一併在教材匯入頁送出，再到工作中心按「電子書」選這一本閱讀。
