## 1. 衡鑑 AI 系統架構圖（CONFIRMED - 概念定義）

```
[使用者 / 沙盒事件]
        ↓
[專業工具引擎] ←→ [規則計算 / 數值模型 / 法規檢索]
        ↓
[衡鑑 HENGJIAN AI]  ← 獨立專業審計模型（未來自行部署微調）
        ↓
[暗星 DARK STAR]  ← 中央協調 / 任務派送 / 改善追蹤
        ↓
[人工覆核] → [改善方案] → [再次模擬] → [稽核報告]
```

**角色分離（必須維持）：**
- 暗星：協調與追蹤，不直接做專業審計推理。
- 衡鑑：獨立專業審計模型，負責財稅法律、財政風險、證據鏈、專業分析。
- 工具引擎：確定性規則、數值計算、法規檢索、模擬。不得以 prompt 假裝成模型。

**沙盒流程：** 假想事件 → 規則引擎計算 → 衡鑑專業分析 → 暗星協調提醒 → 人工覆核 → 改善 → 再次模擬 → 稽核報告。

**狀態：** CONFIRMED（架構定義）；實際模型推理目前 BLOCKED。

## 3. 模型授權及硬體需求（CONFIRMED - 規格）

- **授權：** 優先 MIT / Apache 2.0。TAIDE 需同意其條款並遵守 Gemma Terms。禁止未經審核使用有商用限制或地域限制的模型。
- **硬體（推論）：**
  - TAIDE 12B Q4：~8GB VRAM（或統一記憶體）
  - Qwen3.8-27B Q4：~18GB VRAM（RTX 4090 / 24GB 級）
  - 微調：需更多顯存或雲端免費額度（第一階段不執行實訓）
- **成本：** 第一階段零付費（使用現有硬體或本地量化）。禁止購買 GPU 或付費 API。
- **部署：** 自行部署（llama.cpp / vLLM / Ollama），模型權重本地保管，不依賴外部推理服務。

**狀態：** CONFIRMED（規格）；實機推理測試 REQUIRES TEST。

## 4. 訓練資料規劃（CONFIRMED - 規劃）

- 來源：公開法規、政府資料開放平台、公開稽核報告、合成假想案例（禁止使用真實個資）。
- 格式：指令微調（instruction + CoT + 證據鏈）。
- 隔離：訓練資料 / 模擬資料 / 正式業務資料 三層完全隔離。
- 版本：每筆資料記錄來源 URL、版本、生效日期、更新時間、hash。
- 第一階段：建立資料卡樣板與小規模合成集，不執行實際微調。

**狀態：** CONFIRMED（規劃）；實際資料集 NOT VERIFIED。

## 5. 財稅法律知識庫設計（CONFIRMED - 設計）

**優先法規：**
- 稅捐稽徵法、所得稅法、加值型及非加值型營業稅法
- 納稅者權利保護法、預算法、決算法、審計法、公共債務法
- 行政程序法、個人資料保護法、政府採購法

**資料結構：**
- 每法條：法規名稱、條文、生效日、修正日、來源（law.moj.gov.tw）、版本 hash、最後更新時間。
- 檢索：混合檢索（關鍵字 + 向量），帶來源證據。
- 更新機制：定期比對官方來源，過期法條明確標註。

**狀態：** CONFIRMED（設計）；實際建置 NOT VERIFIED。

## 6. AI 評測及盲測計畫（CONFIRMED - 計畫）

- 訓練前後比較：相同測試集。
- 盲測資料集：未參與訓練的案例（合成 + 公開案例改寫）。
- 測試維度：法規正確性、風險辨識、證據鏈完整性、幻覺率、偏誤、不確定性表達。
- 安全測試：提示註入、越權、敏感資料泄漏、輸出可追溯性。
- 回退機制：模型版本管理，失敗時回退至前版 + 規則引擎。

**狀態：** CONFIRMED（計畫）；實際執行 REQUIRES TEST。
